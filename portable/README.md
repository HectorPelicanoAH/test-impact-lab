# Test Impact Portable

An independent foundation for adding impact analysis to different projects through a skill, deterministic adapters, and common artifacts.

**Status: initial E0 extraction.** Inspection and the viewer work. Full graph generation, per-test coverage, baselines, selection, and the CI runner will be developed following the [SDD](docs/SDD.md). See the [implementation state](docs/IMPLEMENTATION-STATE.md).

## Try it now

Requires Node.js 22 or later. No dependency installation, compilation, or lab services are needed.

From this root:

```sh
node bin/impact.mjs --help
node bin/impact.mjs inspect --root /path/to/project --out /tmp/inspection.json
node bin/impact.mjs view examples/system.json
```

The last command prints a local URL. The sample is explicitly illustrative: it does not simulate executions or claim measured coverage.

Inspection reads manifests and enumerates candidates by pattern. It does not execute project scripts or configuration and is not yet an authoritative test catalogue.

## Using the common UI

The default UI is **Code / Graph / Tests**, starting with the complete graph.
Search centers a node without removing graph facts; pan, zoom, minimap and
framing preserve stable positions. The auxiliary node table stays paginated.
The inspector shows archived source and the recorded origin of a relationship
when available. Missing source bytes or exact ranges stay explicit.

The CLI and v2 bridge retain their original inspection-only behavior. This UI
does not add baseline capture, impact selection or native test execution.
Precompiled browser and viewer assets are included in every standalone export;
no runtime dependency installation or build is required. See [viewer](docs/VIEWER.md).

## Open lab data

The bridge accepts a v2 graph or the full archive generated by test-impact-lab:

```sh
node bin/impact.mjs import-v2 /path/to/snapshot-v2.json --out /tmp/view.json
node bin/impact.mjs validate /tmp/view.json
node bin/impact.mjs view /tmp/view.json
```

To browse archived bytes, add `--include-sources` when importing an archive containing `sources` and `configuration`. Available locator hashes are checked. Without this option, references are preserved but contents are not copied.

A v2 import does not certify a baseline or turn reviewed subjects into coverage. The `test-impact-view/1` format is for inspection; the complete bundle contract will be developed in P2.

## Create the new repository

You can use this directory directly as the root. To obtain a clean copy in another empty directory:

```sh
node scripts/export.mjs /empty/path/test-impact
cd /empty/path/test-impact
git init
git add .
git commit -m "Initial portable test-impact toolkit"
```

The exporter copies code, UI, skill, documentation, sample, and checks. It does not copy Git history, installed dependencies, generated data, or demo applications. It rejects nonempty destinations.

Create a remote and push afterward using your chosen name and account.

## Install the CLI in a consuming project

The current distribution supports local installation:

```sh
cd /path/to/consuming-project
npm install --save-dev /path/to/toolkit
npm exec -- impact inspect --root .
```

You can also always invoke `node /path/to/toolkit/bin/impact.mjs`. Publishing to a registry is unnecessary for trying it.

## Install the skill

Copy `skills/test-impact-onboard/` into your agent's skills directory. In an environment using `~/.codex/skills/`:

```sh
mkdir -p ~/.codex/skills
cp -R skills/test-impact-onboard ~/.codex/skills/
```

Then open the consuming project and invoke:

> Use $test-impact-onboard to inspect this project, identify its needs, and prepare its onboarding SDD.

The skill is self-contained. When the CLI is available, `impact info` lets it locate the toolkit SDD and capabilities. It does not require this lab to be present.

## Planned final experience

This is the SDD's target workflow; baseline/check/run commands **are not implemented yet**:

1. The skill inspects the project, writes its SDD, and configures/implements its adapters.
2. `impact baseline create` generates the graph, catalogue, and attributable coverage for the registered matrix.
3. `impact check --base origin/main --working-tree` calculates selection without running tests.
4. `impact run --analysis <id> --collect-coverage` executes the plan and updates evidence.
5. `impact view` lets you inspect artifacts through the common UI.
6. CI retrieves a compatible baseline, calculates impact, executes, and publishes evidence. It operates without AI.

Insufficient evidence broadens selection or triggers the full available suite. Absence of hits does not imply absence of impact.
